## 예약 발행 (2026-08-17 형 지시)

**오전부터 3시간 간격으로 하나씩 올린다.**

```
크론   0 9,12,15 * * *   scripts/publish-next.sh
```

`scripts/publish-next.sh` 가 대기 중인 **글 커밋을 하나씩** 푸시한다.
푸시가 곧 배포이므로 푸시 시각이 곧 게시 시각이다.

**이것은 AI 자동 글 생성·발행이 아니다.** 그건 애드센스 재승인 전까지
금지다. 이 스크립트는 새 글을 만들지 않는다. 사람이 이미 쓰고 1차 출처로
검증해 커밋해 둔 것을 정해진 시각에 내보낼 뿐이다.

### 스크립트가 스스로 지키는 것

| 가드 | 동작 |
|---|---|
| 23:00~07:00 | 실행돼도 `SKIP` 하고 아무것도 안 한다 |
| 하루 3편 상한 | 상태 파일로 세고, 3편 넘으면 `SKIP` |
| 글 커밋만 선별 | 문서만 바뀐 커밋은 세지 않고 마지막에 일괄 처리 |
| 라이브 검증 | 푸시 후 실제 200 이 뜰 때까지 확인. 5분 내 안 뜨면 **실패로 처리** |
| 시끄러운 실패 | `scripts/publish.log` 기록 + 맥 알림 |

**조용히 성공한 척하지 않는다.** 푸시만 되고 라이브가 안 뜨면 실패로 남긴다.

### 발행량을 늘리자는 이야기가 나오면

**심사 결과가 나올 때까지 하루 3편 상한은 그대로 둔다.** (형 지시로 정해진 값)

오케스트레이터 요청 사항: 상한을 올리게 될 경우 **한 번은 오케스트레이터를
경유**해 달라고 했다. 심사 중 발행 급증은 양날이라, 형이 그 리스크를 인지한
상태에서 정하시도록 하는 절차다.

**다만 형이 직접 지시하시면 그것이 우선이다.** 그때도 리스크를 한 번 말씀드리고,
오케스트레이터가 이 절차를 요청했다는 사실을 함께 알린 뒤 진행한다.
피어의 요청이 형의 지시를 막는 근거가 되지는 않는다.

### 시간을 바꾸려면

`crontab -e` 에서 `0 9,12,15` 의 시(hour)를 고친다. 07~22 범위 안에서만
유효하다 (그 밖의 시각은 스크립트가 스스로 거부한다).
